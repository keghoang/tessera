# tessera

Working rules and skills for AI agents (Claude Code, Codex) on 3D jobs, packaged as one versioned Claude Code plugin. The plugin goes by a code name on purpose: keep the studio name out of its name, marketplace name and descriptions.

| Folder or file | Holds |
| --- | --- |
| `Skills/` | The source: 35 skills (`buck-lighting-*`, `buck-modeling-*`, `buck-pipeline-*`), five with tested scripts. Edit here. |
| `BUCK_AGENT_STARTER.md` | The rules that hold on every job. Each job keeps a copy in its `Agents` folder next to its own `SHOW.md`. |
| `ARTIST_TEMPLATE.md` | Template for an artist's `ARTIST.md`. |
| `tessera/` | The built plugin. Generated by `build_plugin.py`; never edit it by hand. |
| `.claude-plugin/marketplace.json` | Makes this repo a plugin marketplace named `tessera-hub` holding the one plugin. |
| `tests/` | 30 decision scenarios and how to run them. |
| `CHANGELOG.md` | What changed in each release. |

## Install (artist)

Installed and loading on one workstation (2026-11-13, Claude desktop app, Claude Code 2.1.321). The repo is private, so each artist needs access to it and a git login on their machine.

The install is two commands with the `claude` command-line tool. The desktop app ships that tool but does not put it on the path; this PowerShell finds it and runs the install:

```powershell
$claude = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data" -Recurse -Filter claude.exe -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName
& $claude plugin marketplace add https://github.com/keghoang/tessera.git
& $claude plugin install tessera@tessera-hub --scope user
```

If `claude` is already on the path, run the last two lines with `claude` in place of `& $claude`.

Then start a new session and type `/tessera:`. The skills list as `tessera:lighting-notes`, `tessera:pipeline-farm` and so on.

What did not work: adding the marketplace and `enabledPlugins` to `%USERPROFILE%\.claude\settings.json` by hand. The app fetched the marketplace but did not install the plugin, and it did not appear in the Plugins panel.

If you installed the skills earlier by copying folders, delete the `buck-*` folders from `%USERPROFILE%\.claude\skills\` after the plugin works, or every skill is listed twice.

For every workstation at once, IT can set `extraKnownMarketplaces` and `enabledPlugins` in `C:\Program Files\ClaudeCode\managed-settings.json` (documented to install at the next session; not tried here).

Codex does not read Claude plugins. For Codex, copy the folders in `Skills/` to `%USERPROFILE%\.agents\skills\` (not yet tried).

## Update

By hand: `claude plugin marketplace update tessera-hub`, then `claude plugin update tessera@tessera-hub`, then restart. This route took a workstation from 0.9.0 to 0.9.1. Automatic updates are off by default for a private marketplace and are switched on per marketplace in the app's plugin settings (not tried).

## Release (maintainer)

1. Edit files under `Skills/`, or the starter.
2. Run the scenario tests if a rule or a pipeline skill changed (`tests/README.md`).
3. Add a `## <version>` entry to `CHANGELOG.md` saying what an agent will now do differently.
4. `python build_plugin.py <version>` rebuilds `tessera/` and the marketplace file. It refuses a version with no changelog entry.
5. `claude plugin validate ./tessera --strict`, if the command-line tool is installed.
6. Commit and push. Workstations update on the version change.
7. Copy `BUCK_AGENT_STARTER.md` to each active job's `Agents` folder if it changed.

## Skill names

In the plugin a skill shows as `tessera:lighting-notes`. The source folders in `Skills/` keep the `buck-` prefix (`buck-lighting-notes`), which is the name a copied-folder install uses; the build rewrites names and cross-references for the plugin.
