# buck3d

Buck's working rules and skills for AI agents (Claude Code, Codex) on 3D jobs, packaged as one versioned Claude Code plugin.

| Folder or file | Holds |
| --- | --- |
| `Skills/` | The source: 35 skills (`buck-lighting-*`, `buck-modeling-*`, `buck-pipeline-*`), five with tested scripts. Edit here. |
| `BUCK_AGENT_STARTER.md` | The rules that hold on every job. Each job keeps a copy in its `Agents` folder next to its own `SHOW.md`. |
| `ARTIST_TEMPLATE.md` | Template for an artist's `ARTIST.md`. |
| `buck3d/` | The built plugin. Generated by `build_plugin.py`; never edit it by hand. |
| `.claude-plugin/marketplace.json` | Makes this repo a plugin marketplace named `buck-studio` holding the one plugin. |
| `tests/` | 30 decision scenarios and how to run them. |
| `CHANGELOG.md` | What changed in each release. |

## Install (artist)

Status: the package follows the documented format but has not been installed on a workstation yet. The repo is private, so each artist needs access to it and a git login on their machine.

Claude Code command line:

```
claude plugin marketplace add https://github.com/keghoang/buck3d.git
claude plugin install buck3d@buck-studio
```

Claude desktop app (Code tab): add this to `%USERPROFILE%\.claude\settings.json`, restart the app, then enable `buck3d` under **+** > **Plugins**.

```json
{
  "extraKnownMarketplaces": {
    "buck-studio": {
      "source": { "source": "git", "url": "https://github.com/keghoang/buck3d.git", "ref": "main" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": { "buck3d@buck-studio": true }
}
```

If you installed the skills earlier by copying folders, delete the `buck-*` folders from `%USERPROFILE%\.claude\skills\` after the plugin works, or every skill is listed twice.

IT can do the same for every workstation by putting that JSON in `C:\Program Files\ClaudeCode\managed-settings.json`.

Codex does not read Claude plugins. For Codex, copy the folders in `Skills/` to `%USERPROFILE%\.agents\skills\` (not yet tried).

## Update

With `autoUpdate` on, a workstation picks up a new version at its next session. By hand: `claude plugin update buck3d@buck-studio`.

## Release (maintainer)

1. Edit files under `Skills/`, or the starter.
2. Run the scenario tests if a rule or a pipeline skill changed (`tests/README.md`).
3. Add a `## <version>` entry to `CHANGELOG.md` saying what an agent will now do differently.
4. `python build_plugin.py <version>` rebuilds `buck3d/` and the marketplace file. It refuses a version with no changelog entry.
5. `claude plugin validate ./buck3d --strict`, if the command-line tool is installed.
6. Commit and push. Workstations update on the version change.
7. Copy `BUCK_AGENT_STARTER.md` to each active job's `Agents` folder if it changed.

## Skill names

Inside the plugin a skill shows as `buck3d:buck-lighting-notes`. `build_plugin.py --strip-prefix` builds them as `buck3d:lighting-notes` instead; the text inside the files keeps the `buck-` names either way.
